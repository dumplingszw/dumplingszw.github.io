用 Fork 的方式读开源项目

想搞懂一个优秀的开源项目，光看 README 和文档效率很低。我更习惯 fork 下来，动手改。

具体做法：

  1. fork 仓库，本地跑起来（先确保能 build、能 dev）
  2. 挑一个你最感兴趣的功能，顺着调用链读代码
  3. 改一点东西（换个文案、加个日志、改个参数），看行为怎么变
  4. 把“为什么这样设计”记成笔记

这种“破坏性阅读”逼着你真正理解每一层，也比纯浏览记得牢。我 fork 过不少 Agent / AI 工具仓库，基本都是这个路子。
